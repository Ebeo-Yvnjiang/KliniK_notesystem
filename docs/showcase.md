# AdventureX 2026 展示说明

## 项目一句话

“笔记系统”是一个面向长期学习资料重构的本地知识管理系统。它把 Markdown / MDX 笔记提升为可管理的节点图，支持稳定身份、可变组织关系、内容编辑、图一致性检查和 AI 建议确认流程。

## 解决的问题

真实学习笔记不是静态文件夹：

- 同一道题可能同时关联原始笔记、模块总结、错因、复习卡和后续补充；
- 模块名称会改，分类会移动，内容会合并；
- 如果只靠文件路径或中文名称做主键，长期维护会不断漂移；
- AI 整理很有用，但不能无审计地改写私人权威内容。

本项目把这些问题当作数据建模和安全操作问题处理。

## 已完成的系统能力

- 全局稳定 `node_id`；
- `primary_parent_id` 组织树；
- `edges` 跨节点关系；
- 节点创建、移动、排序、归档、恢复、合并和删除空节点；
- 正文编辑、哈希冲突检测和 `manual_override`；
- 全文搜索；
- 图备份、恢复、审计和一致性检查；
- 阶段 B 分类建议试运行：导出任务包、导入 AI 建议、人工确认后提交。

## 技术与工程能力体现

### 需求拆解

项目从“物理错题拆分”逐步拆解出稳定 ID、节点关系、权限、审计、回滚、搜索、编辑器和 AI 建议流。每轮只闭合有限目标，避免一次性重写。

### 数据建模

核心模型从固定模块层级升级为通用节点图：

```text
node_id
+ primary_parent_id
+ typed edges
+ optional content_path
```

节点类型只描述用途，不再决定节点能力。

### 安全操作设计

管理操作必须经过预览、版本校验、备份、提交和审计。内容编辑也使用哈希检测，避免旧页面静默覆盖新修改。

### 长期维护意识

索引、统计和报告都被视为派生数据，尽量从权威图数据重建。`manual_override` 防止生成脚本覆盖人工编辑。

### AI 协作开发与 AI 产品边界

阶段 B 不训练模型、不自动移动节点、不直接改写内容。AI 只输出建议 JSON，用户确认后才调用现有安全图操作。

## 为什么适合作为个人项目展示

这个项目不是一个简单 CRUD demo。它展示的是：

- 从真实个人需求中抽象数据模型；
- 处理隐私和本地文件系统安全；
- 设计可恢复的危险操作；
- 把 AI 放在“建议者”而不是“权威写入者”的位置；
- 用测试和一致性检查保护长期演化。

## 当前边界

- 公开仓库不包含真实私人笔记；
- 当前 demo 数据只用于展示结构；
- 暂未接入外部 AI API；
- 暂未实现多用户、网络部署和复杂权限 UI；
- OCR、题干补全、复习卡压缩是后续方向。

## 下一步计划

1. 扩展 demo 数据和文档；
2. 把阶段 B 建议流用于更多未分类内容；
3. 引入更多学科的导入流程；
4. 生成可审核的解析草稿和复习卡；
5. 在保证隐私与权限的前提下探索网络部署。
